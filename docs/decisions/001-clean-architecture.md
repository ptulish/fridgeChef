# ADR 001: Выбор Clean Architecture

## Статус
Принято.

## Контекст
FridgeChef сочетает работу с реляционными данными (рецепты, версионирование, инвентарь), алгоритмический доменный анализ (сопоставление продуктов, безопасные конверсии размерностей, обновление вкусового профиля) и внешние сервисы (Google Gemini API, Auth, хранилища). Необходимо изолировать бизнес-правила от внешних фреймворков и библиотек.

## Решение
Разделение кодовой базы backend на 4 чётких слоя:
1. `domain`: сущности, Value Objects, чистые доменные сервисы (`UnitConverterService`, `PantryMatcherService`, `TasteProfileUpdaterService`). Отсутствие внешних зависимостей.
2. `application`: Use cases, интерфейсы репозиториев (порты), DTO.
3. `infrastructure`: SQLAlchemy 2.0 модели и репозитории, адаптер Gemini через `google-genai`, Alembic.
4. `presentation`: FastAPI роутеры, схемы Pydantic, внедрение зависимостей.

## Последствия
- Бизнес-логику можно полностью протестировать без поднятия базы данных и без обращений к сети.
- Любой внешний компонент (ORM, AI SDK, Auth провайдер) может быть заменён без переписывания доменной модели.
