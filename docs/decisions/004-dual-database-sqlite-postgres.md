# ADR 004: Двухрежимная стратегия базы данных (SQLite для быстрой разработки и PostgreSQL для продакшена)

## Статус
Принято.

## Контекст
Для полноценного продакшен-развёртывания и строгого соблюдения типов (`JSONB`, `NUMERIC`) идеален PostgreSQL 16. Однако для быстрой локальной разработки, быстрого запуска тестов и ситуаций, когда Docker Desktop не запущен, необходим вариант мгновенного запуска с нулевыми внешними зависимостями.

## Решение
1. Использовать SQLAlchemy 2.0 с универсальными типами данных:
   - `JSON` вместо диалект-специфичного `JSONB` на уровне базовой модели, с маппингом на `JSONB` в PostgreSQL и на нативный `JSON` в SQLite.
   - `String(36)` / `UUID` с fallback для SQLite.
2. Конфигурация через переменную окружения `DATABASE_URL`:
   - По умолчанию для локального запуска: `sqlite+aiosqlite:///./fridgechef.db`
   - Для Docker Compose: `postgresql+asyncpg://postgres:postgres@db:5432/fridgechef`
3. Поддержка обоих режимов в скриптах запуска (`docker-compose.yml` и `run-local.sh`).

## Последствия
- Разработчик может запустить всё приложение за 5 секунд без поднятия тяжелых контейнеров.
- Продакшен-конфигурация сохраняет надёжность PostgreSQL.
