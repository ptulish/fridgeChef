# ADR 003: Эволюционирующая карточка вкусов (Taste Profile Card) и интеграция с Gemini

## Статус
Принято.

## Контекст
Пользователь имеет выраженные кулинарные особенности: любит соусы в обильном объёме, баланс сладкого/кислого/чесночного, но гиперчувствителен к соли (соевые и готовые вок-соусы часто пересаливают блюдо). Кроме того, вкусовые привычки могут меняться. Если передавать в ИИ изолированный запрос «предложи рецепт из курицы», результат будет стандартным и не учтёт личный опыт.

## Решение
1. За каждым пользователем закрепляется `UserTasteProfile`.
2. После каждой сессии приготовления отзыв (оценки 1-5 по вкусу, соли, соусу, кислоте, сладости, текстуре) обрабатывается `TasteProfileUpdaterService`. Если соль оценена на 4 или 5, в карточке фиксируется строгое правило «Уменьшать соевый соус, разбавлять водой, не солить».
3. При любом обращении к AI-модулю (Google Gemini API via `google-genai`):
   - Карточка вкусов компилируется в структурированный кулинарный промпт.
   - Модель отвечает строго по схеме (Structured JSON Output), гарантируя соблюдение ограничений по соли, пропорциям соуса и запрещённым ингредиентам (грибы, перец).
   - Сгенерированный рецепт валидируется Pydantic и требует подтверждения пользователем перед сохранением.

## Последствия
- Высокая персонализация каждого AI-ответа без необходимости пользователю повторять свои вкусы каждый раз.
- Безопасность: модель не имеет прямого доступа к базе данных.
