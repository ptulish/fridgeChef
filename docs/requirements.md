# FridgeChef — Спецификация требований (Requirements)

## 1. Концепция и цель проекта
**FridgeChef** — персональный интеллектуальный веб-сервис для подбора и адаптации рецептов на основе реального содержимого домашнего холодильника, персональных вкусовых предпочтений пользователя, истории приготовления и отзывов.

### Главные принципы
1. **Строгое различие между фактами и предположениями:**
   - Историческое упоминание продукта $\neq$ его наличие сейчас.
   - Начальный импорт продуктов помечается статусом `needs_confirmation` (требует подтверждения) с количеством `NULL`.
   - Неизвестное количество означает необходимость взвесить/проверить, а не бесконечный запас.
2. **Неизменность оригинальных рецептов:**
   - Исходный рецепт никогда не перезаписывается по отзыву.
   - Отзывы пользователя (например, «слишком солёно») порождают **новую личную версию рецепта** (`RecipeVersion`), сохраняя всю цепочку родительских связей (`parent_version_id`).
3. **Эволюционирующая карточка вкусов (Taste Profile Card):**
   - За пользователем закреплена динамическая карточка вкусового профиля.
   - Карточка автоматически обновляется по результатам отзывов (чувствительность к соли, баланс соуса, острота).
   - Карточка передаётся в ИИ (Google Gemini) при каждом запросе подбора или модификации блюда.
4. **Безопасная конвертация единиц:**
   - Преобразования допускаются только внутри совместимых размерностей (масса $\leftrightarrow$ масса, объём $\leftrightarrow$ объём).
   - Масса и объём не приравниваются автоматически (100 г $\neq$ 100 мл).

## 2. Кулинарный профиль пользователя

- **Мясо и белок:**
  - Предпочтения: говядина, свинина.
  - Курица: ранее не любил, но регулярно готовит. Исключать нельзя.
  - Рыба: положительное отношение.
  - Сосиски: нравятся немецкие, не нравятся российские.
- **Блюда и кухни:**
  - Китайский вок, мясо с лапшой (рисовая Bánh Phở, удон), сладко-кислые и терияки соусы, болоньезе.
  - Разделение соусов: обязательное разграничение **маринада** и **основного соуса**.
- **Вкусовой баланс:**
  - Требуется насыщенный, обильный соус, покрывающий мясо и лапшу.
  - Баланс: сладкий + кислый + чесночный. Острота регулируемая (по желанию).
  - Высокая чувствительность к соли: не солить автоматически, учитывать соль в готовых соусах (Wok-соус, соевый соус).
- **Нелюбимые продукты:** грибы, болгарский перец (не предлагать по умолчанию).
- **Оборудование:** сковорода, мультиварка/скороварка, духовка.
- **Стандартная порция мяса:** около 200 грамм.

## 3. Функциональные требования (MVP)

### F1. Мой холодильник (Pantry)
- Просмотр списка продуктов с группировкой по категориям.
- Статусы: `in_stock`, `low`, `out`, `needs_confirmation`.
- Быстрое подтверждение наличия и количества для продуктов со статусом `needs_confirmation`.
- Редактирование количества, единицы измерения, срока годности и заметок.

### F2. Рецепты и подбор (Pantry Matcher)
- Каталог базовых и личных рецептов.
- Расчёт готовности блюда:
  - Достаточно ингредиентов (sufficient).
  - Недостаточно количества (insufficient, расчёт точного дефицита).
  - Отсутствует обязательный ингредиент (missing required).
  - Отсутствует опциональный ингредиент / гарнир (missing optional).
  - Требует проверки в холодильнике (needs confirmation).
- Масштабирование порций (с учётом флага `scalable`).

### F3. Режим готовки (Cooking Sessions)
- Пошаговое руководство с таймерами и крупным шрифтом для кухни.
- Чек-листы для ингредиентов маринада, основного соуса и основы.
- Фиксация фактических отклонений во время готовки.
- Опциональное подтверждение списания продуктов из инвентаря.

### F4. Отзывы и эволюция рецептов (Reviews & Adaptations)
- Детальный отзыв: общий вкус (1-5), солёность (1-5), количество соуса (1-5), сладость, кислота, текстура.
- Кнопка «Создать личную адаптацию»: ИИ или пользователь корректируют рецепт (например, уменьшить соевый соус на 40%, добавить воды 30 мл) $\to$ сохраняется версия 2.

### F5. Карточка вкусового профиля (Taste Profile Card)
- Визуальное отображение текущих вкусовых коэффициентов и привычек.
- Автоматическая корректировка на основе отзывов.
- Возможность ручной правки пользователем.

### F6. AI-шеф (Google Gemini)
- Генерация нового рецепта под доступные продукты и карточку вкусов.
- Предложение корректировки текущего рецепта при негативном отзыве.
- Все ответы ИИ валидируются строгой Pydantic-схемой и сохраняются только после одобрения пользователем.

### F7. Список покупок (Shopping List)
- Формирование списка из недостающих ингредиентов выбранного рецепта.
- Автоматическое объединение совместимых количеств.
- Отметка о покупке и перенос в холодильник.

### F8. Двуязычный интерфейс (RU / EN)
- Мгновенное переключение языка интерфейса без перезагрузки страницы.

## 4. Нефункциональные требования
- **Архитектура:** Clean Architecture (Domain $\to$ Application $\to$ Infrastructure / Presentation).
- **Платформа:** Работа локально (SQLite/FastAPI/Vite) и в контейнерах (Docker Compose + PostgreSQL).
- **Безопасность:** Изоляция пользователей, валидация всех входящих данных через Pydantic.
